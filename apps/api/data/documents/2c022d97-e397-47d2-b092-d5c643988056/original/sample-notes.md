# SlimX Reader — Sample Notes

This is a small example document you can open in SlimX Reader to try out reading,
highlighting, commenting, indexing, and grounded Q&A.

## What is retrieval-augmented generation?

Retrieval-augmented generation (RAG) grounds a language model's answer in retrieved source
passages instead of relying only on the model's parametric memory. A RAG pipeline typically:

1. **Parses** a document into structured text, preserving page and section boundaries.
2. **Chunks** the text into retrieval-sized units that keep related content together.
3. **Embeds** each chunk into a vector.
4. **Indexes** the vectors so they can be searched.
5. **Retrieves** the most relevant chunks for a question.
6. **Generates** an answer that cites those chunks.

SlimX-RAG performs all six steps. SlimX Reader only orchestrates them and shows you the
evidence.

## Why local-first matters

Running the whole pipeline locally means your documents never leave your machine. Embeddings
are computed by a local model, the vector index lives on disk, and answers are generated by a
local model such as Llama 3.2 via Ollama. Cloud providers remain an explicit opt-in.

## A fact to retrieve

The MiniLM sentence-transformer model used by SlimX-RAG's default local embedder produces
**384-dimensional** embedding vectors. Try asking SlimX Reader: *"What is the embedding
dimension of the default local embedder?"* — the answer should cite this section.
